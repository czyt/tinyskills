# 教学使命与练习路线

## 使命

让学习者/agent 从“定制一个桌面”进阶为能解释并维护发行版全生命周期的工程师；每个决策都有制品、验证与失败恢复路径。默认实验环境是一次性 VM，不是用户当前系统。

本 skill 是可移植工程参考，不在使用者仓库根目录擅自建立课程状态。用户确实要多次教学时，在其确认的学习目录维护 mission、resources、learning-records；不知道的能力先用小练习测，不虚构“已经掌握”。

## 每次一课的反馈回路

1. 先让学习者用自己的话回答一个检索题。
2. 讲一个紧邻目标的知识点，给当前官方来源和一个具体文件。
3. 在一次性实验环境完成一个小交付物。
4. 检查真实结果，指出差异；失败保留日志再修，不只读参考答案。
5. 记录能独立完成的行为和待复习项；下一次交错练习已学内容。

不把“看过”“agent 生成了脚本”“语法通过”当作能独立安装/恢复。涉及数据损失的练习只用测试盘，并展示设备身份。

## 课程路径

| 课 | 小目标与产物 | 即时反馈/通关 |
|---|---|---|
| 1 | 画出 rootfs、live、ISO、target 的关系 | 能解释为何 rootfs tar 不等于可安装 ISO |
| 2 | 用 pacstrap 在 VM 建目录树，导出包清单 | 查到 `/usr`、内核与 pacman DB，指出缺少的 boot/用户步骤 |
| 3 | 构建首张 releng 实验 ISO | 用 OVMF 启动、联网、保存日志；不是只看构建退出码 |
| 4 | 给一个自己的配置打包 | 非 root clean build、安装/卸载文件所有权正确、用户配置不被覆盖 |
| 5 | 建临时签名仓库 | 正常包可验签，篡改包/未知 key 被拒绝；不降低 SigLevel |
| 6 | 为一块 GPU/网卡建立适配记录 | 解释 kernel/firmware/initramfs/userspace 各层，真机验证或标未知 |
| 7 | 独立 Hyprland/Quickshell 会话 | 登录/锁屏/portal/输入法可用，切到另一桌面不抢服务 |
| 8 | 安装计划与 OOBE 状态机 | 测试盘新装，断电后能续跑，密码不进日志 |
| 9 | 更新与配置迁移 | 完整升级；坏迁移不标成功；fresh install 不重跑旧迁移 |

| 12 | 发布候选 | 带制品摘要、测试矩阵、已知问题、签名和支持期限的 release packet |

## 检索题与判分依据

先提问，学习者回答后才展示判分要点：

- **为什么只改 archiso profile 的 pacman.conf，开机后却仍用旧源？** 区分构建、live、target 三份配置。
- **Btrfs root 快照回退后 pacman 说版本仍是新的，哪里可能分错？** 检查 `/var/lib/pacman` 是否在另一恢复单元；不手改数据库“修版本”。
- **预制 LUKS 镜像换口令后，每台卷密钥是否独立？** keyslot/password 与 volume key 是两层；仅换密码不能证明独立。
- **把 T2 的 brcmfmac 参数复制给 M 系列，为什么可能反而没网？** Intel quirk 与 Apple Silicon 固件路径不同，回到源码条件和平台文档。
- **更新器显示 boot check 成功，能否说已经验证下次能启动？** 检查实现是否 no-op、是否真的重启，以及健康判据。

## 间隔与真实世界反馈

下一课先回忆上一课的一个失败案例；完成更新课时再穿插 rootfs/包数据库边界；完成 Apple 课时再解释通用 UEFI 的适用范围。向社区提问应带精确机型、制品摘要、内核/boot 版本、脱敏日志、复现步骤和已排除项，不只发“无法启动”。

社区入口通过官方项目页面选择，遵守各社区对衍生发行版求助范围的规则；不要把自有发行版故障冒充纯 Arch 故障。
