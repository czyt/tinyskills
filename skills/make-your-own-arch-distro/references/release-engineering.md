# 构建、验证、发布与长期维护

## 1. 工厂分离权限与网络

流水线按“取源→隔离构建→测试→签名→推广”分权。PR 构建、第三方 PKGBUILD、包安装 hook 均可能执行代码；不能让不可信 PR 读取签名凭证、访问发布存储或复用带秘密的持久 runner。

固定构建器镜像 digest、工具链、上游仓库快照/时间、包清单和源码 commit。原生与交叉构建分开；QEMU user emulation 能跑程序不代表该设备可从固件启动。

“可重建”是步骤可再执行；“可复现”需要相同输入得到同字节并比较摘要。设置 `SOURCE_DATE_EPOCH` 等仅是手段，不能替代双次独立重建的证据。记录不可复现来源，如压缩时间戳、生成密钥和滚动仓库。

## 2. 最低交付清单

- 配方/补丁/配置、精确包名版本与摘要、builder 信息、源提交、仓库世代。
- ISO/rootfs/设备镜像、签名 checksums、独立验证公钥/指纹渠道、构建日志。
- 支持矩阵、兼容 boot/firmware、已知问题、安装/升级/恢复步骤。
- 许可证、源码获取/修改说明、第三方 firmware 来源与再分发边界；SBOM 可从包和源码身份生成，不能只是包名列表冒充完整供应链证明。
- release notes、最低可升级版本、破坏性变更、数据迁移和降级限制。

秘密扫描覆盖 Git 历史、压缩镜像解包后的内容、日志和 CI artifacts。别只检查工作树。

## 3. 测试金字塔

| 层 | 测什么 | 不证明什么 |
|---|---|---|
| 静态 | shell/PKGBUILD/QML 语法、配置/schema、链接 | 能启动、可安装 |
| 构建 | clean chroot、依赖、文件所有权、签名 | 特定固件/GPU 支持 |
| VM 启动 | ISO/UEFI、TTY、网络、图形最小会话 | 实体 Wi-Fi/睡眠/电源安全 |
| VM 安装 | 空白盘、加密、离线、用户初始化 | 每种实体存储/启动固件 |
| 升级/恢复 | 支持旧版本→新版本、断电、回退、reset | 所有未知组合 |
| 真机 | 按支持矩阵冷启动、外设、休眠、温控 | 未测机型的兼容性 |

Windows 共存至少使用测试 Windows 安装/受控 VM 磁盘，验证 ESP 与 BitLocker 行为；不能在开发者日常电脑上“试着跑擦盘流程”。Apple 矩阵按精确机型、SoC、内核、boot/firmware 和功能表记录。

每条证据含：制品摘要、环境/机型、用例、观测、日志、日期、失败或缺测项。零 exit code 不是完整证据；必须断言用户可观测结果，比如新用户真的能登录、Wi-Fi 断网后能重新连接。

## 4. 发布门禁

1. 包与仓库签名验证，旧 keyring 客户端可升级，镜像无私人身份/凭证。
2. 新装与覆盖支持的旧版升级通过，offline 选项真实可用。
3. 新内核/驱动经启动与真机测试，恢复集与救援介质已演练。
4. 支持硬件的关键功能无阻断回归，未测项不宣传支持。
5. 发布候选制品直接推广，不在最后一刻重新构建；上传次序与镜像窗口不导致 DB/包失配。

未满足时标记候选/实验；阻断数据丢失、无法启动、信任链失败的正式发布。灰度和遥测默认最少数据、明确选择、可禁用，不能上传包日志中的 token 或个人配置。

## 5. 运营与退役

维护安全公告/Arch news、上游 ABI 与 boot 变更；分派 CVE 修复负责人和应急发布步骤。保留支持窗口内的仓库世代、镜像、恢复包与密钥轮换资料，监测镜像可用性、磁盘空间和证书过期。

定义 EOL：提前通知、迁移至上游/下一版、数据导出与解密、撤销设备凭证、清理发行版自己的启动项，不删除其他 OS。仓库下线前提供签名归档或清楚的迁出步骤，不能让用户只能用“关闭签名”续命。

## 6. 学习其他发行版的方法

- **EndeavourOS**：查看官方 ISO 配方与安装流程，学习 Arch 基底、live 系统和桌面选项如何分工。
- **CachyOS**：查看官方包配方/内核/ISO 仓库，学习自定义内核与硬件策略的维护成本，而不是照搬优化 flags。
- **Fedora Asahi Remix / Asahi**：学习 Apple 平台的引导与硬件功能表；它们不是 Arch 包仓库，不能混装 RPM 或推断与某个 Arch 镜像同等支持。
- **Omarchy**：学习默认配置、first-boot、平台扩展和更新/恢复编排；外部包工厂/镜像不是仅靠当前主仓就能证明。

这些是比较入口，不代表本 skill 已审计它们的全部代码。取某项目实现时另行固定 commit、阅读相关文件与历史，并补独立测试。

一个已查阅的具体对照是 [CachyOS Live ISO 的 CHANGELOG.md](https://github.com/CachyOS/CachyOS-Live-ISO/blob/master/CHANGELOG.md)：其 25.08 历史记录包含为规避启动问题调整 live 内核、为安装目标提供备用内核，26.01 记录加强 alongside 安装的 ESP 容量检查。可迁移原则是**live 与 target 内核策略分开，双系统安装做实际容量预检**；不要把某次发行版本的内核或固定 ESP 尺寸提升为通用标准。

依据：[发行版官方工程入口](sources.md#比较研究)，[构建/包工具](sources.md#基础与包)。
