# Refactoring UI 设计指南

浓缩自 Adam Wathan & Steve Schoger 的《Refactoring UI》（面向会写代码但没有设计背景的开发者）。

**核心原则：设计不是"把东西修饰得好看"，而是做出一连串受约束的决策。** 先建体系（一组有限的选项），再从体系里挑值，而不是每次从无限选项里凭感觉选。

## 设计工作流（按顺序执行）

**输入：** ①要设计/改进的功能（一个真实功能，不是应用外壳）；②目标用户（决定个性方向）；③品牌主色（存在则准备其色阶）。**输出：** 设计方案——已定义的体系（字号/间距/颜色/阴影/圆角）+ 所有取值均来自该体系 + 灰度优先、层级明确的界面。

1. **从功能开始，不从外壳开始。** 别先画导航栏/侧边栏/logo——先设计一个真实功能（如"搜索航班"）的最小界面。
2. **灰度设计。** 完成布局前不要引入颜色，逼自己用间距、对比度、大小撑起画面；低保证草图用粗马克笔，避免抠细节。
3. **细节留到后面。** 初期不碰字体、阴影、图标。
4. **小步循环。** 设计一个功能的简单版 → 实现它 → 在真实界面上迭代 → 再做下一个。不要一次设计完所有功能，别在抽象层面想象边界情况。
5. **当个悲观派。** 新功能默认很难做，只设计能交付的最小版本；"锦上添花"的部分晚点再设计。
6. **定个性。** 个性由四个具体因素决定，选好后全界面保持一致，不再混搭：
   - 字体：衬线=优雅经典；圆润无衬线=活泼；中性无衬线=朴素。
   - 颜色：留意感受——蓝=安全熟悉、金=昂贵、粉=有趣不严肃。
   - 圆角：大圆角=活泼；小圆角=中性；无圆角=严肃正式。**同一界面不要混用直角和圆角。**
   - 措辞：正式语气=官方专业；随意语气=友好。
7. **限制选项。** 提前建好体系，以后所有决策从体系里挑：字号、字重、行高、颜色、间距、尺寸、盒阴影、圆角、边框宽度、不透明度。用排除法：猜一个值，和它相邻的两个值放一起对比，淘汰明显不行的，直到只剩一个。

🔴 **CHECKPOINT（动手设计前）：** 明确三件事再开始——①要做的功能及最小交付范围（不包含任何"锦上添花"）；②目标用户（决定个性和措辞方向）；③品牌主色是否存在（有则准备它的色阶）。三件缺一，先补齐再画布局。

## 视觉层级（最有效的设计工具）

- **大小不是一切。** 突出主要元素用字重（600/700），弱化次要元素用更浅的颜色，而不是极端字号。避免 400 以下字重。
- **界面只保留 2-3 种颜色**：深色（主要内容）、灰色（次要）、更浅灰（第三级）。
- **彩色背景上禁止用灰色文字**——用户看到的只是对比度降低。正确做法：基于背景色手动挑一个新颜色（同色相，调饱和度和明度）。不要用"白字+降不透明度"。
- **用弱化来强调。** 元素不够突出时，弱化与它竞争的元素（未激活导航项用更柔和的颜色、侧边栏去掉背景色）。
- **标签是万不得已的。** 数据用格式/上下文就能识别时（邮箱、电话、价格），不加标签。需要标签时合并进值（"12 left in stock" 而非 "In stock: 12"）。仪表盘场景标签次要化（调小、降低对比度）；用户明确在找标签时（技术规格页）才强调标签。
- **视觉层级 ≠ 文档层级。** 区块标题常常是辅助内容，可以做小甚至视觉隐藏；按语义选标签，按视觉需求设计样式。
- **字重与对比度互相补偿。** 图标比文字重，用更柔和的颜色降低对比度；1px 细边框太淡时，加粗比加深颜色更柔和。
- **操作按钮按层级设计，不是按语义：**
  - 主要操作（每页通常只有一个）：实心、高对比度背景色，一眼可见。
  - 次要操作：描边或低对比度背景色，清晰但不抢眼。
  - 第三级操作：链接样式，能被发现但不打扰。
  - 破坏性操作：不是主要操作就按次要/第三级处理，把"大而红"留给确认步骤。

## 布局与间距

- **留白是减出来的，不是加出来的。** 一开始给多得多空间，再一点点减；单独看"略多"的量在完整界面里往往"刚刚好"。紧凑只在仪表盘这类场景做刻意选择。
- **间距/尺寸体系用非线性阶梯**（相邻取值差距 ≥25%）：小尺寸端取值密（12→16 是 33% 增幅），大尺寸端取值疏（500→520 只差 4%）。用 16px 做基准，用因数与倍数搭建。示例起点：4、8、12、16、24、32、48、64、96、128、192、256（小端密、大端疏，按需增删）。
- **不需要填满屏幕。** 600px 够用就用 600px；边缘留白无害。单区块不需要跟随导航做通栏。
- **画布缩小。** 大画布上设计小界面困难时，从 400px 宽移动端画布开始，再放大。
- **用分栏思考。** 内容在窄宽度下最好（表单），把它拆成多栏而不是整体加宽。
- **栅格被高估了。** 侧边栏这类用固定宽度（针对内容优化），主内容区弹性伸缩；组件内部同理。**别为了上栅格缩小元素**——给 max-width，只有屏幕更小时才强制缩小。
- **相对尺寸无法通用。** 大屏上很大的元素在小屏上缩得比小元素更快。组件属性独立缩放：大按钮内边距更宽松，而不是等比放大。
- **避免含糊间距。** 分组靠间距表达时，组外间距 > 组内间距，否则用户分不清标签配哪个输入框、列表项是否独立。

## 文字排版

- **字号阶梯手工定制**（别用模数阶梯，会产生小数和过死跨度；别用 em 单位，嵌套会算出阶梯外的值——只用 px/rem）。一套实用阶梯：12、14、16、18、20、24、30、36、48、60、72。
- **选字体：** 拿不准就系统中性无衬线字体栈（`-apple-system, Segoe UI, Roboto, Noto Sans, Ubuntu, Cantarell, Helvetica Neue`）；过滤掉少于 5 种字重的字体；正文别用 x 高度小、字形压缩的字体；按热度排序选有性格的字体；去研究喜欢的网站用什么字体。
- **行长 45-75 字符**（网页上 20-35em）。段落与图片混排时，即使内容区更宽，段落宽度也要单独限制。
- **混排字号按基线对齐，不居中。**
- **行高与行长、字号成反比关系：** 行长越长行高越大（窄内容 1.5，宽内容可达 2）；字号越小行高越大，大标题行高 1 完全没问题。
- **链接不一定用颜色。** 全是链接的界面里，用更重的字重或更深的颜色即可；边缘链接只在悬停时加下划线。
- **对齐以可读性为准：** 超过两三行的文字不居中（太长就重写文案）；表格数字右对齐；两端对齐必须开断词。
- **字距：** 用宽字距字族做标题时收紧字距；全大写文字加大字距提升可读性。

## 色彩

- **用 HSL 建模颜色**（色相 0-360°、饱和度、明度），不要用 hex 调色——HSL 才能直觉地做色阶。
- **调色板不是 5 个颜色，是三组色阶：**
  - 灰色：8-10 阶（从很深灰到白，不要用纯黑）；文字、背景、面板、控件全靠它。
  - 主色：5-10 阶；浅阶做带色背景（提示框），深阶做文字。
  - 强调色：黄/粉/青等，加语义状态色（红=破坏、黄=警告、绿=向好）；每色也要多阶，但使用克制。
- **搭色阶流程：** 选基色（适合当按钮背景）→ 选最深阶（留给文字）和最浅阶（做背景染色）→ 补中间。九阶（100-900）：先补 700/300，再补 800/600/400/200。灰色同理。**这不是科学，最终靠眼睛微调，但不要频繁加新色阶。**
- **明度偏离 50% 时提高饱和度**，否则浅阶/深阶会发灰。
- **用色相旋转改变明暗**（保留色彩浓烈感）：变亮朝 60°/180°/300°，变暗朝 0°/120°/240°；每次旋转不超过 20-30°。为黄色做深阶时向橙色转，避免发闷发褐。
- **灰色可以带色温：** 加一点蓝=冷灰，加一点黄/橙=暖灰；深浅色阶也要同步加饱和度。
- **无障碍：** 正文对比度 ≥4.5:1，大字 ≥3:1。彩色背景+白字难达标时，反转关系（浅背景+深色文字）；深色面板上的彩色文字，把色相朝更亮的颜色（青/品红/黄）旋转来提高对比度。
- **不要只靠颜色传达信息**：状态变化配图标；图表折线靠明暗对比而不是不同颜色（色盲用户）。

## 层次感

- **光从上方来。** 凸起元素：上沿稍亮（上边框或带垂直偏移的内阴影）+ 下方小范围深色阴影（模糊半径几个像素，边缘锐利）。内凹元素：下沿稍亮（下边框或负偏移内阴影）+ 顶部内阴影。浅色要手动挑，不用半透明白（会吸走饱和度）。别追求照片级真实。
- **阴影传达高度：** 模糊小范围小=略高于页面；模糊大范围大=离用户近、抓注意力。建立 5 档阴影体系：小阴影（按钮）→ 中阴影（下拉菜单）→ 大阴影（弹窗）。示例起点（offset / blur / 颜色）：`0 1px 2px rgba(0,0,0,.06)`、`0 2px 4px rgba(0,0,0,.06)`、`0 8px 16px rgba(0,0,0,.08)`、`0 16px 32px rgba(0,0,0,.1)`、`0 32px 64px rgba(0,0,0,.12)`。
- **阴影配合交互：** 拖拽项被拿起时加阴影、按钮按下时减小或去掉阴影——别想阴影本身，想元素该在 z 轴的哪个位置。
- **双层阴影**：第一层大而柔和（模拟直射光投影），第二层小而暗（模拟物体下方环境光缺失）。高度越高，内层小阴影越轻微。
- **扁平设计也能有层次：** 比背景浅=浮起，比背景深=凹进；用不模糊、只垂直偏移的实心阴影。
- **重叠出层次：** 卡片跨两种背景的交界、元素比父容器高、控件压在轮播图上。图片重叠时加一圈与背景同色的"隐形边框"。

## 图片

- **用好照片：** 特定需求请摄影师，通用需求用图库/Unsplash。不要用占位图，也别指望手机随手拍。
- **文字需要稳定对比度（4 招）：**
  1. 半透明蒙版：黑蒙版压暗亮部衬白字，白蒙版提亮暗部衬深字。
  2. 降低图片对比度（同时调亮度补偿）。
  3. 着色：降对比度 → 降饱和度 → multiply 混合模式叠纯色（还能配品牌色）。
  4. 文字阴影：大模糊半径、零偏移的淡淡光晕。
- **每张图用该有的尺寸：** 别把小图标放大 3-4 倍（装进带背景色的形状里）；别把全尺寸截图缩小 70%（改用平板尺寸截图、只截一部分、或画简化版界面）；小尺寸用 favicon 时要重画极简版，别让浏览器硬缩。
- **用户上传内容：** 固定尺寸容器 + `background-size: cover` 居中裁剪，别让图片撑乱布局；防背景渗色用轻微内阴影或半透明内边框，不用实色边框。

## 收尾打磨

- **把默认样式做到极致：** 项目符号换图标（对勾/箭头/贴合内容的挂锁）、引用放大换色、链接用粗的彩色自定义下划线、表单用品牌色自定义复选框/单选按钮。
- **强调色边框加点颜色：** 卡片顶部、当前导航项、提示消息侧边、大标题下方、布局顶部——一条彩色矩形就能让设计"看起来做完了"。
- **装饰背景：** 换背景色、双色渐变（色相差 ≤30°）、低调可重复图案（Hero Patterns）、简单几何形状。背景装饰对比度压低，不干扰内容。
- **空状态是优先事项：** 插画/图片吸引注意 + 突出的行动号召；没内容前藏起标签页、筛选器等无用操作。
- **少用边框**，依次考虑：阴影（元素与背景色不同时最有效）→ 两种略有区别的背景色（已有背景色就删掉边框）→ 加大间距。
- **跳出框框：** 下拉菜单可以是带区块、多列、辅助文字的多彩盒子；表格可以合并列、加图片和颜色；重要的单选按钮可以做成可选卡片。

## 持续进阶

- 看到喜欢的设计问自己：**"这位设计师做了什么我根本想不到的事？"**（背景反转、按钮放进输入框、标题用两种颜色……）
- **重建你最喜欢的界面，不偷看开发者工具**——自己的版本和原版差在哪，就是你要学的技巧。

## 反例黑名单（不要做）

| # | 不要做 | 替代做法 |
|---|--------|---------|
| 1 | 一上来设计整个应用外壳（导航/侧边栏/logo） | 先设计一个真实功能 |
| 2 | 一开始就上色、抠字体/阴影细节 | 灰度设计，细节留到后面 |
| 3 | 每个像素值都试一遍（12px vs 13px、阴影 10% vs 15%） | 从提前定好的体系里挑值 |
| 4 | 用极端字号建立层级 | 用字重和颜色 |
| 5 | 彩色背景上用灰色文字或"白字+降不透明度" | 手动挑一个接近背景色的颜色 |
| 6 | 给所有数据加"标签：值" | 合并标签与值，或让格式自解释 |
| 7 | 所有操作按钮都按语义上色（一个红一个绿） | 按层级设计：主/次/三级 |
| 8 | 间距用线性 4px 倍数体系 | 相邻差距 ≥25% 的非线性阶梯 |
| 9 | 填满整个屏幕、元素全做通栏 | 给每个元素刚好需要的空间 |
| 10 | 用栅格百分比给侧边栏、登录卡片定宽 | 固定宽度 + max-width |
| 11 | 用 em 单位定义字号阶梯 | 只用 px/rem |
| 12 | 行长超过 75 字符 | 限制在 45-75 字符 |
| 13 | 彩色背景+白字硬凑 4.5:1 对比度 | 反转对比关系（浅背景+深字） |
| 14 | 用 lighten/darken 函数临时算色阶 | 提前定好固定的 5-10 阶色阶 |
| 15 | 明度偏离 50% 时保持饱和度不变 | 提高饱和度防止发灰 |
| 16 | 只用颜色区分信息（红绿涨跌、图表折线） | 配图标或用明暗对比 |
| 17 | 放大 16px 的小图标做功能区块 | 装进带背景色的形状里 |
| 18 | 缩小全尺寸截图塞进小空间 | 更小屏截图、截局部或简化界面 |
| 19 | 元素之间全靠边框区分 | 阴影、背景色差异、间距 |
| 20 | 空状态随便放段文字了事 | 插画 + 行动号召，藏起无用操作 |

## 失败模式速查（症状 → 修复）

| 症状 | 修复 |
|------|------|
| 界面"糊成一团"，看不出重点 | 建立层级：弱化次要信息（浅灰/小字重），只突出 1-2 个主要元素 |
| 设计看起来挤、压抑 | 间距从"多得多"开始减，而不是从"刚好不糟"开始加 |
| 彩色背景上文字发闷发白 | 同色相手动调饱和/明度挑文字色，或反转对比关系 |
| 浅色/深色色阶发灰发白 | 明度偏离 50% 时提高饱和度；灰色系加色温 |
| 标题和正文混排看着别扭 | 按基线对齐；大标题收紧字距、行高降到 1 |
| 文字压在图片上看不清 | 蒙版 / 降图片对比度 / 着色 / 文字阴影，按需组合 |
| 两个元素该分开却分不清 | 组间间距 > 组内间距；仍不行再考虑阴影、背景色、最后才是边框 |
| 深色面板里次要文字达不到对比度 | 把色相朝更亮颜色（青/品红/黄）旋转，而不是往白色调 |
| 卡片浮不起来 | 上沿浅色高光 + 下方小范围锐利阴影；或与背景色差异拉开 |
| 阴影太脏/太重 | 拆两层：大而柔和 + 小而暗；高度高的元素内层阴影更轻微 |

## 使用说明

- 本指南是决策参考：设计前先快速过一遍「设计工作流」，具体环节查对应章节。
- 所有数值（字号阶梯、色阶数量、阴影档位、对比度比值）是起点不是终点——体系的价值在于"选项有限"，不在于数字本身。
- 内容浓缩自《Refactoring UI》（Adam Wathan & Steve Schoger 著），原书含 284 张插图与大量对比示例，需要完整语境时查阅原书（refactoringui.com）。

🔴 **CHECKPOINT（每个主题完成后）：** 对照「反例黑名单」和「失败模式速查」自查当前设计，命中任一条 → 先修复再继续下一个主题。
